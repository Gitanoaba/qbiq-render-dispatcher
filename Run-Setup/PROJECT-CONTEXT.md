# qbiq Render Dispatcher - Project Context

> **For Claude / anyone new to this project: read this document FIRST before changing anything.** It contains all the context needed to understand what this system does, how it's organized, and how to make changes without breaking things.

---

## 1. What this project is

An automated render system for qbiq.ai. Designers create "tickets" from their PC (a `.json` file that points to a `.rvt`), tickets sync via Dropbox to a dedicated PC (the **Render Server**), and a Revit plugin on that PC processes the tickets automatically: it opens the .rvt, configures Enscape (preset + skybox + view path XML), and triggers the video export.

**Result:** designers don't have to keep their PC busy during a render. They submit the ticket and go on with their work.

## 2. Architecture (3 PC roles)

```
┌─────────────────────┐     ┌─────────────────────┐     ┌─────────────────────┐
│   DESIGNER PC(s)    │     │      DROPBOX        │     │   RENDER SERVER PC  │
│  (Eitan 3D, others) │     │  (#_RenderServer/)  │     │   (Eitan Abaud)     │
│                     │     │                     │     │                     │
│  Plugin: Sender     │────▶│  pending/*.json     │────▶│  Plugin: Server     │
│  - Create Ticket    │     │  processed/*.json   │     │  - GO RENDER SERVER │
│                     │◀────│  failed/*.json      │◀────│  - View Log         │
│                     │     │  logs/dispatch.log  │     │  - Create Ticket    │
└─────────────────────┘     └─────────────────────┘     └─────────────────────┘
```

- **Designer PC**: any team member's Revit machine. Only has the **sender** plugin (Create Ticket button only).
- **Dropbox**: shared folder `#_RenderServer/` that acts as a work queue. Subfolders: `pending/`, `in-progress/`, `processed/`, `failed/`, `logs/`.
- **Render Server PC**: dedicated machine with Revit + Enscape. Full **server** plugin, ideally with Revit running all day long.

## 5. Versioning

Scripts have a version in their header (`Version: 1.0.0-server` or `Version: 1.0.0-sender`). When you make a change:

1. Bump the version number in 3 places inside the script:
   - Comment in the header (line 14)
   - Banner printed via Write-Host (line ~50)
   - `<Version>` inside the .csproj (line ~180)
2. Add an entry to **CHANGELOG.md**
3. **If the sender plugin changed**: rebuild the DLL and replace `deploy/QbiqRenderDispatcher.dll` (run `Run-CreateTicket.bat` to compile, then copy the output DLL into `deploy/`).

---

## 6. Workflow for plugin changes

1. **Identify which script to edit:**
   - Server-only change (auto-poll, render automation) → `Setup-RenderDispatcher-Server.ps1`
   - Change that affects ticket creation → both scripts (server + sender share the `CreateTicketCommand.cs` and `CreateTicketDialog.cs` code)
2. **Edit the `.ps1`** (C# code lives inside as here-strings `@'...'@`). Watch out for:
   - Don't break here-strings: the closing `'@` or `"@` must be in column 0, no leading whitespace
   - Very large edits can truncate the file — prefer many small edits
3. **Verify script integrity**:
   ```bash
   # Count here-string pairs (must match)
   grep -c "@'\$" Setup-RenderDispatcher-Server.ps1   # openers
   grep -c "^'@\$" Setup-RenderDispatcher-Server.ps1  # closers
   ```
4. **Test:** close Revit, run `Run-Setup-Server.bat` (or sender), open Revit, verify.
5. **If sender changed** (CreateTicket): rebuild the DLL and update `deploy/`.
6. **Update CHANGELOG.md.**

## 7. Current features (as of today)

### Server plugin (Render PC)
- **GO RENDER SERVER**: process the next pending ticket
- **View Log**: opens `logs/dispatch.log` in Notepad
- **Create Ticket**: create a ticket for the open .rvt
- **Auto-poll mode** (`AutoRenderHandler.cs`): timer that checks `pending/` every N seconds and processes the next ticket without human intervention
- **Path remapping**: rewrites paths from user "Eitan 3D" to "Eitan Abaud" so referenced .rvts resolve locally
- **Idling-event coordinator** (`RenderCoordinator.cs`): automation runs in `UIApplication.Idling` events so Enscape can load geometry between steps
- **Detailed logging** in `logs/dispatch.log` with per-step timestamps
- **Slack notifications** (optional, set `$SlackWebhookUrl` in the script)

### Sender plugin (designer PCs)
- **Create Ticket**: dropdown with presets (Qbiq preset by default), dropdown with skyboxes (scans project folder + Skybox Library), dropdown with view paths (scans project folder for .xml files), Revit view locked to "3D Enscape"
- The .rvt path comes from `Document.PathName` (zero typos possible)
- Output filename auto-derived: `<Project> VIDEO_<id>.mp4`

### Hardcoded settings (never asked to the user)
- Resolution: Full HD (1920x1080)
- Compression: Maximum
- FPS: 60

## 8. Quirks / gotchas

1. **Enscape needs the Revit main thread to be free to load geometry.** That's why render automation runs in `Idling` events, not inline. Don't add long `Thread.Sleep` calls without thinking it through.
2. **Revit's ribbon uses WPF, not standard UI Automation.** That's why the plugin uses `Autodesk.Windows.ComponentManager.Ribbon` (via `AdWindows.dll`) to find and click the "Start Enscape" button.
3. **Enscape's `RendererWindow` appears before Enscape is actually ready.** After detecting it, we wait `PostVsOpenDelaySeconds` (default 45s) to give it time to finish loading geometry before touching Visual Settings.
4. **The skybox takes 10-15s to apply.** The coordinator explicitly waits.
5. **PowerShell `$ErrorActionPreference = 'Stop'` + dotnet stderr**: in Step 4 of the build, we wrap `dotnet build` in `cmd.exe /c` and relax ErrorAction to 'Continue' so stderr writes don't abort the script.
6. **The plugin doesn't detect whether it's running as server vs sender.** Behavior is determined by which script compiled it (the server script includes `AutoRenderHandler.cs`, the sender doesn't).
